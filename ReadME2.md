OwlEye TroubleMaker Application & Monitoring Dashboard
Project Overview
This project consists of two components:

TroubleMaker Application: A Python-based chaos engineering tool that simulates system stress events such as CPU overloads, memory spikes, directory overflow, and database errors.

Prometheus & Grafana Dashboard: A server monitoring system that collects, visualizes, and alerts on system metrics and stress events generated by the TroubleMaker Application.

Part 1: How to Run the TroubleMaker Application
Install Requirements
The TroubleMaker app uses standard Python libraries. Install any missing libraries with:

pip install -r requirements.txt
Launch the CLI Application From the /TroubleMakerApp directory:

python run.py
You will be presented with a menu to:

 - Trigger CPU Overload
 - Trigger Memory Spike
 - Trigger Directory Overflow
 - Trigger Database Error
 - Schedule Events (one-time or recurring)

Optional: Run Cleanup Scripts After stress tests, you can manually run cleanup scripts inside /cleanup/ to reset the environment.

Part 2: Prometheus and Grafana Setup
1. Prometheus Setup
Install Prometheus on your server or local machine (if not already installed).

Use the provided prometheus.yml configuration file.

Key configuration points:

Scrapes metrics from:

Node Exporter (localhost:9100)

Custom TroubleMaker metrics (localhost:9000 or other custom exporters)

Start Prometheus:
./prometheus --config.file=prometheus.yml
2. Grafana Setup
Install Grafana (if not already installed).

Start Grafana and login (default: admin/admin).

Add Prometheus as a Data Source.

Import the provided grafana_dashboard.json OR manually create a dashboard with panels like:

CPU Usage

Memory Usage

Directory Overflow Event Count

Database Error Count

3. Alert Rules
Alerts were configured in Grafana to:

Trigger when CPU usage > 80%

Trigger when memory usage > 80%

Detect sudden surges in directory file count

Detect error spikes in database metrics

Alert actions can trigger HTTP webhooks to auto-run cleanup scripts if desired.

Key Components and Technologies
Python 3.8+ (TroubleMaker)

Prometheus (Metrics scraping and alerting)

Grafana (Visualization and Alerting UI)

Node Exporter (System Metrics)

Important Notes
Event Duration: CPU and Memory events are designed to run long enough for Prometheus to scrape and Grafana to detect them.

Scheduling: TroubleMaker allows scheduled chaos experiments using Python’s sched module.

Metrics: Events write to a .prom file that Prometheus scrapes regularly.

Auto-Resolution: Cleanup scripts simulate recovery actions and can be linked to Grafana alerts via webhook integrations.

Known Issues
- Very short CPU or memory events may sometimes not get caught by Prometheus if the scrape interval is too long.

- Directory overflow events require careful monitoring to avoid actual disk space exhaustion.

Future Improvements
- Add more fine-grained stress types (e.g., disk I/O stress).

- Dockerize the entire stack (TroubleMaker + Prometheus + Grafana).

- Integrate direct webhook callbacks from Grafana to auto-trigger cleanup.
